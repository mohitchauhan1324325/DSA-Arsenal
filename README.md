## 🧠 Problem-Solving Framework

```text
Read Problem → Understand Constraints → Identify Pattern → Think of Brute Force
		 → Optimize → Choose Data Structure → Write Template → Test Edge Cases
		 → Analyze Complexity → Code
```

| Stage | What to do |
|---|---|
| **Read problem** | Restate the task and identify the inputs and expected output. |
| **Understand constraints** | Estimate feasible time and space complexity. |
| **Identify pattern** | Look for familiar structures, operations, and invariants. |
| **Think of brute force** | Establish a correct baseline before optimizing. |
| **Optimize** | Reduce repeated work or narrow the search space. |
| **Choose data structure** | Select structures that support the needed operations. |
| **Write template** | Adapt a known pattern to the problem's details. |
| **Test edge cases** | Check empty, minimal, duplicate, and boundary inputs. |
| **Analyze complexity** | State time and space costs. |
| **Code** | Implement, run examples, and verify the result. |

Each problem should ideally include:

- **Problem name** and **pattern**
- **Intuition** and **approach**
- **Complexity**
- **Code**
- **Important edge cases**
